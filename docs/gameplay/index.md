# 核心玩法总览

《CourierSim · 快递王国》的核心玩法围绕**物流网络的搭建与运营**展开，分为六大子系统：

| 子系统 | 一句话 | 详见 |
|--------|--------|------|
| 车辆系统 | 购置、租赁、调度与管理车队（沿真实折线 24h 运行） | [车辆系统](/gameplay/vehicle) |
| 中转仓库 | 建仓、升级、网络中枢（¥60 万） | [中转仓库](/gameplay/hub) |
| 站点建设 | 建站、营销、订单门控端点（¥20 万） | [站点建设](/gameplay/station) |
| 市场宣传 | 提升知名度与货量 | [市场宣传](/gameplay/marketing) |
| 订单与货流 | 站点门控生成、配送、奖励 | [订单与货流](/gameplay/order) |
| 经济与财务 | 收入、成本、借贷、租赁、评分 | [经济与财务](/gameplay/finance) |
| 时间系统 | 小时制推进、24h 运行、倍速控制 | [时间系统](/gameplay/time) |

此外还有四个支撑性系统：**员工与人力**、**科技研发**、**突发事件与 AI 竞争**、**游戏模式**，共同构成完整的经营生态。

## 轴辐式（Hub-and-Spoke）网络模型

本作核心网络模型延续 TransRoute 的轴辐式结构：

- **站点（Spoke）**：货量的入口与出口，直接面对客户，覆盖一片区域。
- **中转仓库（Hub）**：货物集散中心，站点之间不直接相连，通过 Hub 转运。

```
 站点A ──┐                 ┌── 站点C
         ├──▶ 中转仓库 ◀──┤
 站点B ──┘    (Hub)       └── 站点D
```

这与真实快递网络（顺丰、联邦快递）一致：**收件 → 集中 → 干线转运 → 分拣 → 派送**。

## 数值设计原则

- 所有数值集中到数据表（JSON/CSV 资源），逻辑与数据分离，便于调参（见 [数据管理](/development/data-management)）。
- 公式化而非硬编码：货量、成本、时效均由可读公式计算。
- 分 Tier 缩放：城市等级、车辆等级、仓库等级均影响系数，形成平滑成长曲线。
- 反作弊/反膨胀：设成长软上限，避免后期数值爆炸（参考同类游戏的通病）。

## 玩家的一天（示例流程）

1. **晨间结算**：昨日货量生成完毕，看到各站点待发货物。
2. **调度**：把新买的货车分配到"首尔西站 → 釜山枢纽"线路，设置满载率阈值。
3. **扩张**：在大邱新建站点，覆盖东南区域；升级釜山仓库扩容。
4. **推广**：在光州投放一轮"开业促销"，短期拉高货量。
5. **观察**：时间流逝，车辆沿真实路网行驶，货物中转，收到运费。
6. **复盘**：看数据面板，发现某线路爆仓，决定加车或提价。
