# 站点建设（Station）

站点是货量的**入口与出口**，直接面对客户，覆盖一片地理区域。站点网络的密度与布局决定了公司的货量上限。

## 一、站点属性

```
Station {
  id: String
  name: String
  position: Vector2
  geo: {lng, lat}
  level: int              // 1~3（小型驿站 / 标准网点 / 旗舰中心）
  coverage_radius: float  // 覆盖半径（公里）
  daily_capacity: float   // 日收发件量上限
  pickup_cap: float       // 收件能力
  delivery_cap: float     // 派件能力
  staff_slots: int
  cost_per_day: float
  connected_hub: String   // 归属中转仓库
}
```

## 二、覆盖区域规划

**覆盖是站点玩法的核心**。每个站点在真实地图上有一个覆盖半径，覆盖范围内的**人口/商业/工业**区域贡献货量。

- **覆盖数据来源**：真实地理数据（见 [地图数据获取](/map/data-acquisition)）——城市人口密度、商业区、工业区分布。
- **货量模型**：站点货量 ≈ 覆盖区域内需求密度 × 站点等级系数 × 知名度系数。
- **覆盖重叠**：多个站点覆盖重叠区域会**竞争分流**（自己跟自己抢），需合理布局避免浪费。

```
覆盖规划示意（地图俯视）：
   ●站点A 覆盖半径R           ●站点B
   ┌─────────┐
   │  ◜◝     │            ┌─────────┐
   │ ◜  ◝    │            │   ◜◝    │
   │◜  ●───┼─┼────────────┼───●  ◝  │  ← 重叠区货量分流
   │ ◝  ◜    │            │   ◝◜    │
   │  ◝◜     │            │         │
   └─────────┘            └─────────┘
```

## 三、站点等级

| 等级 | 类型 | 日容量 | 覆盖半径 | 特点 |
|------|------|--------|---------|------|
| 1 | 社区驿站 | 200 件 | 2 km | 起步，靠近居民区 |
| 2 | 标准网点 | 800 件 | 5 km | 主力，兼顾收派 |
| 3 | 旗舰中心 | 3000 件 | 10 km | 高吞吐，可做微型枢纽 |

## 四、运营

- **收件（Pickup）**：站点覆盖区内的寄件需求进入站点。
- **派件（Delivery）**：到达的货物从站点派送到客户。
- **营业时间**：可设时段，影响成本与货量。
- **增值服务**：代收货款、保价、包装服务（提升客单价，见 [经济系统](/gameplay/finance)）。
- **升级路径**：升等级 / 增加柜台 / 增加快递员（见 [员工](/gameplay/staff)）。

## 五、选址策略要点

站点选址与仓库不同，更看重**贴近需求**：

1. **高需求区优先**：CBD、商业街、大型住宅区、大学城（真实 POI 数据标注）。
2. **避免重叠**：与已有站点保持距离，覆盖不重叠。
3. **靠近 Hub**：减少集货运输成本。
4. **低成本启动**：地价低的区域先铺开，赚到钱再进高价区。

## 六、技术实现要点

- 站点是地图上的**建筑节点**，用 `Area2D` + 圆形 `CollisionShape2D` 做覆盖检测。
- 覆盖区域高亮：进入"规划模式"时，用半透明圆显示各站点覆盖范围。
- 货量计算放 `DemandSystem`（Autoload），站点只存结果，不逐帧计算。

```gdscript
# 覆盖重叠检测（示意）
func calc_overlap(a: Station, b: Station) -> float:
    var d = a.position.distance_to(b.position)
    var r = a.coverage_radius + b.coverage_radius
    if d >= r: return 0.0
    # 简化：用距离比近似重叠比例
    return clamp(1.0 - d / r, 0.0, 1.0)
```
