# 突发事件与竞争（Events & Competition）

突发事件与 AI 竞争为稳定的经营循环注入不确定性，制造"经营张力"。

## 一、突发事件（Events）

按影响面分为正面/负面/中性，随机按权重触发：

| 类型 | 示例 | 影响 |
|------|------|------|
| 天气 | 暴雨、暴雪、台风 | 运输降速、延误 |
| 油价 | 油价暴涨/暴跌 | 变动成本波动 |
| 需求 | 节日大促、突发爆单 | 货量激增（考验运力） |
| 事故 | 车辆抛锚、仓库火灾 | 直接损失 + 满意度下降 |
| 政策 | 限行、环保新规 | 区域运营受限 |
| 舆情 | 好评爆红 / 差评危机 | 知名度波动 |
| 竞争 | 对手降价、抢客 | 货量被分流 |

**设计原则**：事件应**可应对**——玩家有手段缓解（备用车、买保险、提前囤油、储备运力），而非纯随机惩罚。

## 二、事件应对机制

- **预警**：部分事件有前兆（天气预报、政策预告），玩家可提前准备。
- **保险**：车辆险、仓库险，降低事故损失。
- **应急预案**：预留备用运力、多条线路冗余。

## 三、AI 竞争对手

沙盒模式引入 AI 快递公司，营造竞争生态：

- **对手行为**：AI 会建站、买车、定价、投放广告，按难度分级（温和/激进）。
- **评分竞争**：货量按各公司评分份额分配（延续 TransRoute 模型）：

```
评分 = 时效分 × 价格分 × 覆盖分 × 满意度分 × 知名度分
公司份额 = 公司评分 / Σ 所有公司评分
```

- **差异化**：对手有经营风格（低价抢占型 / 高端时效型 / 区域深耕型），迫使玩家差异化竞争。
- **可交互**：可观察对手动态（公开报表），但不直接操控。

## 四、技术实现要点

- `EventSystem`（Autoload）：事件表（JSON）+ 权重随机 + 触发与结算。
- `AISystem`（Autoload）：对手公司以简化状态机运营（每 tick 决策），与玩家共享同一模拟内核。

```gdscript
# 事件触发（示意）
func roll_events():
    for ev in event_pool:
        if randf() < ev.weight / total_weight:
            emit_event(ev)

# AI 每日决策（示意）
func ai_tick_day(company):
    if company.cash > threshold and company.fleet_util > 0.85:
        company.buy_vehicle()          # 运力不足则买车
    if company.awareness < competitor_avg:
        company.run_ad()               # 知名度落后则投放
```
