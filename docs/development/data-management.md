# 数据管理与配置

## 一、数据分类

| 类别 | 存储 | 说明 |
|------|------|------|
| 静态配置 | `data/config/*.json` | 车型/建筑/货种/科技/事件/经济常数 |
| 区域数据 | `data/regions/*/` | 城市/路网/距离矩阵/需求（烘焙产物） |
| 存档数据 | `user://saves/` | 玩家进度 |
| 设置数据 | `user://settings.cfg` | 音量/分辨率/键位 |
| 本地化 | `data/i18n/` | 多语言词条 |

## 二、配置管理原则

1. **单一数据源**：数值只写在配置文件，代码不硬编码。
2. **可读可 diff**：JSON 格式，便于版本管理与人审。
3. **类型校验**：加载时校验字段类型与范围，坏数据尽早暴露。
4. **热重载（开发期）**：支持改配置即时生效（`ConfigLoader` 缓存失效）。

## 三、配置结构规范

```json
{
  "id": "unique_id",
  "name": "显示名",
  "tier": 1,
  "stats": { "capacity_kg": 800, "speed_kmh": 60 },
  "cost": { "price": 30000 },
  "unlock": { "requires": ["tech_x"] }
}
```

- 字段命名用 `snake_case`，与 GDScript 风格一致。
- `id` 全项目唯一，用于引用。
- `name` 走本地化 key（`name_key`），支持多语言。

## 四、版本管理

- 配置文件随代码进 Git，修改走 PR 评审。
- 配置结构变更需同步更新文档与校验脚本。
- 存档结构变更走版本迁移（见 [存档系统](/architecture/save-system)）。

## 五、数值平衡（Balancing）

### 平衡方法

1. **公式化**：货量/成本/时效用可解释公式，非拍脑袋数字。
2. **曲线表**：成长曲线（等级→数值）用表格 + 插值。
3. **Excel/脚本辅助**：用 Python 脚本跑数值模拟，检查曲线平滑度。
4. **A/B 调参**：开发期可热调参数实时看效果。

### 关键曲线

| 曲线 | 形态 | 说明 |
|------|------|------|
| 货量-知名度 | 对数增长（边际递减） | 防后期爆炸 |
| 成本-等级 | 线性/超线性 | 扩张有代价 |
| 收入-规模 | S 形 | 规模效应 + 瓶颈 |
| 满意度-时效 | 指数衰减 | 违约惩罚 |

### 反膨胀

- 设成长软上限，后期收益增速下降。
- 引入运营成本随规模增长（管理成本、拥堵），抑制无限扩张。

## 六、数据安全与备份

- 存档原子写 + 备份（`.bak`），防损坏。
- 定期自动存档，关键操作前存档。
- 存档文件不加密（单机），但结构健壮可迁移。

## 七、数据校验清单

| 校验项 | 方式 |
|--------|------|
| JSON 合法 | 解析器 + CI |
| 字段类型/范围 | 加载时断言 |
| 引用完整性 | id 引用存在性检查 |
| 路网连通 | 图遍历校验 |
| 距离矩阵对称 | 脚本断言 |

## 八、数据所有权

- 地理数据：OSM（ODbL），署名 + 派生条款（见 [许可](/development/license)）。
- 数值配置：自研，AGPL-3.0。
- 美术/音频：自产或合规素材，记录许可。
