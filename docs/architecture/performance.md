# 性能优化

2D 像素模拟经营游戏性能压力主要来自：地图渲染、车辆寻路、货单模拟。本章给出针对性策略。

## 一、目标帧率

- 桌面：60 FPS 稳定。
- 移动端（未来）：30~60 FPS。
- 地图缩放/平移流畅，无卡顿。

## 二、地图渲染优化

| 策略 | 说明 |
|------|------|
| **分块（Chunk）加载** | 大 TileMapLayer 拆成多个 chunk，视野外卸载 |
| **批量 set_cell** | 用 `set_cells_terrain_connect` / 数组批量，避免逐格 |
| **静态建筑合批** | 站点/仓库精灵用 `MultiMeshInstance2D` 或静态层 |
| **减少透明像素** | 像素图集紧凑，避免超大空纹理 |
| **相机裁剪** | 视野外节点 `visible=false`，Godot 自动剔除渲染 |

## 三、寻路优化

| 策略 | 说明 |
|------|------|
| **分层寻路** | 区域层（AStar2D 粗）+ 道路层（细），精度与性能平衡 |
| **路径缓存** | 车辆行驶路径预计算，移动只插值 |
| **局部失效** | 障碍变化只失效相关路径段，不全量重算 |
| **异步/分帧** | 大规模寻路分摊到多帧，避免单帧卡顿 |

调研结论：分层寻路可将寻路耗时从 45ms 降至 3ms。

## 四、模拟计算优化

| 策略 | 说明 |
|------|------|
| **数据对象不渲染** | 货单用 RefCounted，不进场景树 |
| **批量 tick** | 日结算批量处理，避免逐对象 _process |
| **空间分区** | 站点/仓库用四叉树/网格分区，快速查询 |
| **延迟计算** | 覆盖分析等重计算放空闲帧/后台线程 |

## 五、内存优化

- 区域数据按需加载/卸载（见 [区域切换](/map/region-switching)）。
- 距离矩阵稀疏化：只存城市对，站点级用插值。
- 纹理用合理压缩（像素图可用无损 PNG，避免不必要的大图）。

## 六、GDScript 优化

- 避免逐帧 `new()` 大量对象（复用池）。
- 循环内避免字符串拼接（用 `PackedStringArray` / `%`）。
- 热点函数用 `static` 类型标注（`-> float` 等）提升性能。
- 性能热点经 Profiler 确认后，下放 C# 或 GDExtension。

## 七、Profiling 方法

1. 用 Godot 内置 **Profiler / Monitors** 找瓶颈。
2. 关注 `_process` / `_physics_process` 耗时、节点数量、draw call。
3. 用 GUT 做性能回归测试（关键操作耗时断言）。

## 八、性能预算

| 项 | 预算 |
|----|------|
| 地图瓦片 | 分块，单帧加载 ≤ N 块 |
| 同屏车辆 | ≤ 200（用 MultiMesh 可更多） |
| 货单总数 | 数万级（纯数据无压力） |
| 寻路调用 | 缓存后仅加载/障碍时 |

## 九、优化时机

**原则：先跑通，再优化。** 首版功能优先，用 Profiler 定位真实瓶颈，避免过早优化。目标是在功能完整的前提下维持 60 FPS。
